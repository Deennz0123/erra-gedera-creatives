# TMON tick-scalper — что требуется от владельца счёта

Из среды, где пишется код, хосты `invest-public-api.tinkoff.ru`, `iss.moex.com` и
`developer.tbank.ru` закрыты сетевой политикой. Поэтому **сбор данных выполняется на
вашей машине**, а в разработку возвращаются файлы. Токен вашу машину не покидает.

Обоснование каждого шага — в [FEASIBILITY.md](FEASIBILITY.md).

## Что чем блокируется

| Шаг | Время | Что разблокирует |
|---|---|---|
| 1. Токен на чтение | 5 мин | всё остальное |
| 2. Забрать код | 2 мин | — |
| 3. `schedule` | 1 мин | `instrument_uid`, расписание сессий, проверка что код рабочий |
| 4. `watch` 10 минут | 10 мин | первый реальный взгляд на глубину очереди |
| 5. `collect` 2–3 суток | фоном | режим I или II, потолок циклов, ваша доля очереди |
| 6. Прислать файл | 5 мин | симулятор и оценка в тиках за день |
| 7. Тестовая пара сделок | 10 мин | формат учёта в брокерском отчёте |

Шаг 3 — критический путь: он и проверяет код, и закрывает два открытых вопроса.

---

## Шаг 1. Токен T-Invest, только на чтение

Т-Инвестиции → Настройки → раздел про токены для API → создать токен
**без права на торговлю**. Для сбора данных торговые права не нужны.

**Токен никому не пересылайте**, в том числе в переписку по этому проекту. Он живёт
только в переменной окружения на вашей машине.

## Шаг 2. Забрать код

Нужен Python 3.10 или новее. Ставить ничего не требуется — только стандартная библиотека.

**Если папку прислали архивом** — распаковать, и всё, шаг выполнен. Клонировать не нужно.

Иначе, Linux и macOS:

```bash
git clone -b claude/tmon-tick-trading-automation-ur95a1 \
  https://github.com/Deennz0123/erra-gedera-creatives.git
cd erra-gedera-creatives/tmon-tick-scalper
```

Windows, PowerShell — то же самое, но перенос строки обозначается обратным апострофом,
а не обратным слешем:

```powershell
git clone -b claude/tmon-tick-trading-automation-ur95a1 `
  https://github.com/Deennz0123/erra-gedera-creatives.git
cd erra-gedera-creatives\tmon-tick-scalper
```

Токен через `export` задавать не нужно ни на одной системе: скрипты читают файл `.env`,
он создаётся на следующем шаге. `export` — команда Linux и macOS, в PowerShell её нет.

### Проверить Python

```bash
python3 --version     # Linux, macOS
py --version          # Windows
```

Нужна версия **3.10 или новее**. Дальше в примерах пишется `python3` — в Windows
подставляйте `py`.

> **Почему `py`, а не `python`.** Windows по умолчанию ставит заглушку Microsoft Store,
> которая перехватывает команду `python` и ничего не делает: `python --version` печатает
> голое слово «Python» без номера. Проверить можно так:
>
> ```powershell
> Get-Command python | Format-List Name, Source, Version
> ```
>
> Если в `Source` путь через `WindowsApps`, а `Version` равна `0.0.0.0` — это заглушка.
> Лаунчер `py` идёт с настоящим Python и работает в обход неё. Убрать заглушку совсем:
> Параметры → Приложения → Дополнительные параметры приложения → Псевдонимы выполнения
> приложения → выключить `python.exe` и `python3.exe`.
>
> Запуски в `.vscode/launch.json` на Windows уже используют `py`.

### Если работаете в VS Code

Открывать надо **папку `tmon-tick-scalper`**, а не корень репозитория — проект
самодостаточный, и конфигурация лежит внутри него.

```bash
code erra-gedera-creatives/tmon-tick-scalper
```

Внутри уже настроено:

* **`.vscode/launch.json`** — четыре готовых запуска в панели Run and Debug:
  «расписание торгов», «смотреть вживую», «сбор в файл», «анализ собранного».
  Токен подхватывается из `.env`, в терминале ничего экспортировать не нужно;
* **`.vscode/settings.json`** — тесты через pytest видны в Test Explorer, импорты
  `tmon_bot` и `research` резолвятся;
* **`.env.example`** — скопировать в `.env` и вписать токен.
  **`.env` в git не попадает**, это проверено правилом в `.gitignore`.

**Как создать `.env`:** в панели Explorer слева нажать иконку «новый файл», назвать
файл ровно `.env` (с точкой в начале, без расширения) и вписать одну строку.

Через терминал то же самое — в PowerShell:

```powershell
Set-Content -Path .env -Value 'TINVEST_TOKEN=ваш_токен'
```

В bash:

```bash
echo 'TINVEST_TOKEN=ваш_токен' > .env
```

Содержимое файла — ровно одна строка:

```
TINVEST_TOKEN=ваш_токен
```

Без кавычек и без пробелов вокруг знака равенства. Сохранить.

Скрипты читают `.env` сами, поэтому запуск из терминала работает так же, как из VS Code —
ничего экспортировать не нужно.

VS Code предложит поставить расширение Python — оно нужно и для запусков, и для тестов.

## Шаг 3. Проверка связи и расписание

```bash
python3 research/tinvest_collect.py schedule
```

Ожидаемый вывод — название фонда, `instrument_uid` и три сессии по московскому времени:

```
TMON — Денежный рынок
instrument_uid: 0000-0000-...

2026-08-24 (MOEX):
  утренняя:  06:50 – 09:50
  основная:  10:00 – 18:40
  вечерняя:  19:00 – 23:50
```

**Прислать: весь вывод целиком.** Он закрывает вопрос про утреннюю сессию — если она
есть, торговое окно 990 минут из 1440, а не 810, и непроторгованный разрыв всего 450.

**Если упало** — прислать текст ошибки полностью. Скрипт печатает код ответа и тело.
Против живого API он не проверялся: из среды разработки нет доступа даже к документации,
поэтому имена полей REST-обёртки могли разойтись. Правится за один заход.

## Шаг 4. Посмотреть вживую

```bash
python3 research/tinvest_collect.py watch
```

```
  время    бид / оффер     спред  очередь бид/оффер   сделки за интервал
09:58:31  163.02 / 163.03   1 тик    41200 / 38900     12 шт,   18400 бумаг  (8 по офферу, 4 по биду)
```

**Прислать: 20–30 строк**, желательно из основной сессии. Здесь видно то, чего нет ни на
одном графике: глубину очереди с обеих сторон и с какой стороны идут сделки.

## Шаг 5. Сбор

```bash
mkdir -p data
nohup python3 research/tinvest_collect.py collect data/tmon.jsonl --quiet \
  > collect.log 2>&1 &
```

Требования к запуску:

* **непрерывно, включая вечернюю и утреннюю сессии.** Разрыв между закрытием и открытием
  — это то, что мы измеряем: без него нельзя отличить режим I от режима II;
* машина не должна засыпать. Ноутбук с уходом в сон не подойдёт — либо десктоп, либо
  дешёвый VPS;
* объём примерно **7 МБ в сутки**.

Начните с **двух-трёх суток** — этого хватит, чтобы получить первые настоящие числа.
Десять дней нужны для точности, и о них имеет смысл говорить после первого прогона.

Проверить, что процесс живёт:

```bash
tail -3 collect.log && wc -l data/tmon.jsonl
```

## Шаг 6. Прислать файл

```bash
gzip -k data/tmon.jsonl        # 70 МБ сжимаются примерно до 8–10
```

Прислать `data/tmon.jsonl.gz`. Посмотреть, что получилось, можно и самому:

```bash
python3 research/queue_probe.py analyze data/tmon.jsonl --size 6000
```

Он печатает длину режима, восстановленную `F(t)`, режим I или II, число чередований
между бидом и оффером, потолок циклов и расчётную долю очереди.

## Шаг 7. Одна тестовая пара сделок

Купить один лот лимитной заявкой, продать один лот лимитной заявкой, выгрузить брокерский
отчёт за этот день.

Нужно **не для проверки комиссий** — это вопрос закрытый. Нужен формат учёта: как
считается база FIFO, какие строки по налогу, как отражается частичное исполнение.

**Прислать: строки отчёта по этим двум сделкам.** Суммы можно затереть, важна структура.

## Решения, которые нужны от вас

* **Репозиторий.** Сейчас код лежит внутри `erra-gedera-creatives`, который про креативы
  для соцсетей. Боту там не место. Переносить дёшево, пока кода мало — скажите, заводить
  ли отдельный.

## Если запускать негде

Запасной вариант — сборщик через MOEX ISS, **токен не нужен вообще**:

```bash
python3 research/queue_probe.py collect data/tmon-iss.jsonl --seconds 28800
```

Данные там с задержкой и глубина стакана беднее, поэтому долю очереди по ним не оценить.
Режим I против режима II он покажет, потолок циклов — нет.
