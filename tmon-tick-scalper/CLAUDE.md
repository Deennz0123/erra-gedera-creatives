# TMON tick-scalper — контекст проекта

Инструмент для автоматической торговли паями фонда денежного рынка TMON на счёте
Т-Инвестиций. Сейчас проект на стадии **измерения**: код написан и покрыт тестами, но
живых данных ещё нет, и главный вопрос не решён.

Аналитика целиком — [FEASIBILITY.md](FEASIBILITY.md), редакция 4.
Порядок действий владельца счёта — [README.md](README.md).

## Что уже сделано

```
tmon_bot/market.py       F(t), стакан, позиция (база и слив раздельно)
tmon_bot/policy.py       решающий слой: чистая функция состояния, без сети
tmon_bot/simulator.py    очередь FIFO, прогон политики по собранным данным
research/tinvest_collect.py  сбор через T-Invest API, проверен на живом API
research/queue_probe.py  метрики очереди, режим I или II, потолок циклов
research/simulate.py     вердикт в процентах годовых
run.ps1 / run.bat        весь цикл одной командой
tests/                   44 теста, все зелёные: py -m pytest tests/ -q
```

## Главный вопрос, ради которого всё

**Сколько тиков в день реально снимается пассивными заявками.** Прибыль цикла равна
одному тику, но исполнение зависит от позиции в очереди за маркет-мейкером. Ответ даёт
только измерение: `simulate.py` по собранному стакану.

Порог: меньше **+0,5% годовых** сверх удержания фонда — писать робота не стоит, выгоднее
просто держать TMON.

## Особенности окружения (Windows, разбирались долго)

* **`py`, а не `python`.** Команда `python` перехвачена заглушкой Microsoft Store:
  версия `0.0.0.0`, путь через `WindowsApps`, интерпретатор не запускается.
* **`ca.pem` рядом с проектом.** API Т-Банка использует сертификат Минцифры, которого нет
  в хранилище Windows. Скрипт доверяет только этому файлу и системное хранилище не
  трогает. Пересоздаётся командой из README.
* **`.env` с токеном.** Одна строка `TINVEST_TOKEN=...`, без кавычек и пробелов. Правится
  в редакторе, не через оболочку: PowerShell калечит строку. Токен показывается при
  выпуске один раз.
* **Вставка в терминал VS Code у владельца не работает.** Правый клик, Shift+Insert или
  файлы-запускалки.

## Что делать дальше

1. `py research\tinvest_collect.py schedule` — подтвердить, есть ли утренняя сессия.
   Торговое окно 810 или 990 минут из 1440, разница меняет расчёты на четверть.
2. `py research\tinvest_collect.py watch --minutes 10` — впервые увидеть глубину очереди
   с обеих сторон и с какой стороны идут сделки.
3. `py research\tinvest_collect.py collect data\tmon.jsonl --minutes 480` — сбор.
   Нужен непрерывный, включая вечернюю и утреннюю сессии: разрыв между закрытием и
   открытием мы измеряем.
4. `py research\queue_probe.py analyze data\tmon.jsonl --size 6000`
5. `py research\simulate.py data\tmon.jsonl --sleeve 6000` — вердикт.

## Чего не делать

* **Не бэктестить на свечах.** Цена скачет между бидом и оффером; такой бэктест покажет
  прибыльную возвратную стратегию, которой не существует. Только стакан с очередью.
* **Не строить сигнал на индикаторах.** RSI и Stochastic на этих минутках —
  детерминированная функция чередования bid/ask. Единственный вход —
  фаза режима `(F − bid) / тик`.
* **Не продавать базовую позицию.** Она приносит доходность фонда круглосуточно, включая
  выходные. Оборачивается только слив.
* **Не уходить во флэт на ночь.** Ночь стоит ≈2,5 копейки, выходные ≈17 — это 2,5 и 17
  успешных циклов.
* **Не выходить на тейк-профите.** Он срабатывает по цене последней сделки, а она скачет
  между бидом и оффером: сработает сразу после входа и продаст по цене входа.

## Ключевые числа

```
1 тик = 1 копейка = 248 минут удержания фонда
248 минут = длина одного ценового режима (это одно и то же число)
+1,53% годовых за каждый полный тик, захваченный раз в день
−0,37% годовых за каждый час в день вне позиции
```

Избыток цикла к простому удержанию: `1 тик − дрейф за время вне позиции`.
Положителен тогда и только тогда, когда флэт короче 248 минут.
